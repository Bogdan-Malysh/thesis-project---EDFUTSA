# ARIMA 2025 Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run only the frozen `arima_p2_d1_q2` ARIMA(2,1,2) specification over all 2025 Germany and Austria target dates and append its results to the existing 2025 model tables.

**Architecture:** Add an isolated `arima_test_2025.py` runner that verifies the authoritative 2024 selection and registry, delegates fitting/forecasting/metrics to the existing ARIMA modules, and adds only test-specific checkpoint/output and integrity validation. Merge table rows by `(country, model_family, specification_id)` while retaining Weekly seasonal naive and Holt-Winters rows.

**Tech Stack:** Python, pandas, NumPy, statsmodels through existing ARIMA modules, pytest, project interpreter `.venv\Scripts\python.exe`.

- [ ] **Step 3: Build the exact 2025 manifest**

Enumerate local dates from `2025-01-01` through `2025-12-31`. ```python

Do not pass new optimizer settings, do not alter `fit_arima`, and do not accept a fit whose existing `eligible` property is false. - [ ] **Step 5: Add test-specific checkpoint persistence**

Implement CSV read/upsert/atomic-write helpers using the existing ARIMA key columns. Persist jobs, forecasts, and summaries after each result under `OUTPUT_DIRECTORY`. Require model family `ARIMA`, specification `arima_p2_d1_q2`, trend `n`, finite forecasts, unique UTC timestamps per job and target country, origin/cutoff equality, target counts 23/24/25, and no future local-date rows.
